没有 CLI，AI 怎么"调用工具"、怎么"跑 Python"？

以同事的原型 data_retrieving_published_rl 为例，讲清楚 IMF OpenAI API 下工具调用的原理。

一句话：模型本身什么都不执行。它只会回一段文字，内容是"请帮我调用某个函数，参数是这些"。真正执行的是你电脑上一个普通的 Python 程序：它读到这段请求，自己去跑对应的函数，再把结果发回给模型。这样来回几轮，就是"Agent"。

1三个角色

你电脑上的 Python 程序

同事的 Streamlit 应用。它既是聊天界面，也是"执行员"：所有函数（查 iData、下载数据、跑代码）都在这里运行，用的是你本机的 Python 和 imf_datatools。

IMF OpenAI Gateway

一个网址（API_URL）。程序通过 HTTPS 把消息发过去，gateway 转给 GPT 模型，再把回复传回来。它只传文字，不碰你的电脑。

GPT 模型（云端）

只做一件事：读消息，回消息。回复要么是给用户的文字，要么是一张"工具调用单"（JSON）。它看不到你的文件，也不能运行任何东西。

2为什么 IMF 电脑上能做到

Claude Code、Codex 这类 CLI 被禁止，是因为它们是现成的、能直接在电脑上执行命令的软件。同事的做法不需要任何这类软件：

  • 调用 API 只是一个普通的网络请求，用 pip 装的 openai Python 包就能发。
  • gateway 的接口和 OpenAI 官方格式一样（"OpenAI-compatible"），所以只要把 base_url 改成 IMF 的地址。
  • 身份验证分两层：.env 里的 API_KEY，加上一次 IMF 微软账号登录（msal 包弹出浏览器，token 缓存在本地，之后不用再登）。

对应代码就这几行（imf_openai_helper.py）：

client = OpenAI(
    api_key="DUMMY",                      # 不用 OpenAI 官方 key
    base_url=config["API_URL"],           # IMF gateway 地址
    default_headers={
        "api-key": config["API_KEY"],             # 部门发的 key
        "Authorization": f"Bearer {access_token}", # 微软登录拿到的 token
    },
)

换句话说，CLI 工具里那个"让模型调用工具的循环"，同事用大约 60 行 Python 自己写了一遍（openai_agent.py 里的 run_openai_agent）。

3一次工具调用的完整往返

以"我要美国 2015 年以来的 GDP 增长"为例：

  1. 程序把三样东西发给 gateway：系统提示词（规则）、聊天记录、工具清单。工具清单就是一份"菜单"，写明每个函数叫什么、做什么、需要哪些参数： 
    {"type": "function",
 "function": {
   "name": "search_indicator_catalog",
   "description": "在所选数据库的完整指标列表里搜索并排序",
   "parameters": {"type": "object",
                  "properties": {"query": {"type": "string"}},
                  "required": ["query"]}}}
  2. 模型看完决定"我需要先搜指标"，于是不回答文字，而是回一张调用单： 
    "tool_calls": [{
  "id": "call_01",
  "function": {"name": "search_indicator_catalog",
               "arguments": "{\"query\": \"real GDP growth\"}"}}]
  3. 程序读到调用单，按名字找到本地对应的 Python 函数，用这些参数执行（这里会调用 imf_datatools.get_dimension_values 并排序）。
  4. 程序把执行结果作为一条 role: "tool" 的消息加进对话，再发给模型： 
    {"role": "tool", "tool_call_id": "call_01",
 "content": "{\"candidates\": [{\"code\": \"NGDP_RPCH\", ...}]}"}
  5. 模型读到结果，再决定下一步：继续调用工具（比如查国家代码、下载数据），或者直接用文字回答用户。
  6. 程序重复第 3–5 步，直到模型回的是纯文字，才把答案显示给用户。同事设了上限：最多 32 次工具调用。

循环的核心代码（简化）：

while True:
    response = client.chat.completions.create(
        model="gpt-5.6-terra", messages=messages,
        tools=TOOLS, tool_choice="auto")          # 带上工具清单
    msg = response.choices[0].message
    messages.append(msg)
    if not msg.tool_calls:                        # 没有调用单 = 最终回答
        return msg.content
    for call in msg.tool_calls:                   # 有调用单 = 本地执行
        args = json.loads(call.function.arguments)
        result = _tool_result(call.function.name, args, state)
        messages.append({"role": "tool", "tool_call_id": call.id,
                         "content": json.dumps(result)})

关键点：模型能做什么，完全由程序给它的"菜单"和程序里的 _tool_result 决定。菜单上没有的事，模型做不了；程序也可以在执行前检查参数，不合规就拒绝，比如同事的下载工具会拒绝"没经过搜索验证的代码"。

4"跑 Python 代码"具体是怎么实现的

同事的原型里，"运行 Python"分成两种，很容易混在一起：

A. 固定工具（如下载数据）B. run_python（模型自己写代码）
代码谁写的开发者事先写好的函数模型临时写的一段代码
模型给什么只给参数，如数据库、代码、年份整段代码文本，放在参数 code 里
什么时候执行立刻，在循环里自动执行不自动执行，要用户点按钮
在哪执行Streamlit 程序本身的进程新开一个子进程
结果回给模型吗回给模型不回，只显示给用户

B 的完整流程

  1. 模型回一张调用单：run_python(code="df.groupby('COUNTRY').mean()")。
  2. 程序不执行，只把代码存进待办列表，然后告诉模型"已排队，未执行"： 
    pending_actions.append({"kind": "python", "source": code})
return {"status": "queued_for_workbench_review", "executed": False}
  3. 用户到 Workbench 页面，看到这段代码，勾选"我理解这些命令以我的权限运行"，再点 Run。
  4. 程序（code_runner.run_python）开一个新的 Python 进程来跑： 
    subprocess.run(
    [sys.executable, "-I", "-c", PYTHON_RUNNER, "input.csv", "output.csv"],
    input=code,               # 模型写的代码从标准输入送进去
    cwd=临时文件夹,            # 每次一个新的临时目录
    env=精简后的环境变量,      # 不带 API key 等敏感变量
    timeout=30,               # 超过 30 秒强制停止
    capture_output=True)      # 收集打印输出和报错
    当前数据表先存成 input.csv，在子进程里叫 df；代码把结果赋给 result，就会写到 output.csv，再读回界面显示。

这里的 sys.executable 就是正在运行 Streamlit 的那个 Python。它直接启动 Python，不经过任何 shell，所以在没有 bash 的 IMF Windows 上也能用。

为什么不让模型的代码自动运行：子进程能读写你的文件、访问网络，权限和你本人一样，并不是安全沙箱。模型写错代码或理解错需求，后果会直接落在你的电脑上，所以同事要求人工审核再点 Run。我们架构里 v1 不给模型通用的 run_python，也是同样的考虑：下载只走固定的 idata_fetch。

如果以后想让它像 Codex 一样自动跑

技术上只差一步：在第 2 步直接调用 code_runner.run_python，把打印输出和报错作为工具结果回给模型。模型看到报错就能改代码再试。Claude Code、Codex 的"自己写代码、自己调试"本质上就是这个循环。是否开放，是安全与方便之间的取舍，不是技术难题。

5小结

问题答案
模型在哪里执行代码？任何地方都不执行。它只输出"调用单"。
谁执行？你电脑上的 Python 程序，按调用单去跑本地函数。
为什么不需要 CLI？CLI 里的那个循环，用 openai 包 + 几十行 Python 就能自己写。
模型怎么知道有哪些工具？每次请求都附带一份工具清单（名字、说明、参数格式）。
怎么控制风险？只给需要的工具；执行前在程序里检查参数；能改动电脑的操作需要用户确认。
