iData Agent — Phase 1: Data Retrieval

The user describes the data in plain words. The agent finds the best-matching indicators across IMF databases, the user picks one and confirms countries, years and frequency, chooses the download options and folder, and the program downloads the file. Afterwards the user can ask for copy-paste code in Stata, R or Python that reproduces the download.

Changes typed in the chat

At any step the user can type a change ("make it quarterly", "add China", "use CPI instead"). The AI edits the query sheet and the flow goes back to the earliest affected screen: a new indicator returns to step 3, a new folder to step 4. Values that are still valid stay filled in.

4From plain words to indicator + database: the index

imf_datatools searches database names only and has no cross-database indicator search; its caches last one session. So the team builds a local indicator index ahead of time from the indicator lists of every in-scope database. The databases' own lists remain the only source of codes.

Build time

  1. Scope. get_databases() lists everything the user can see. A team-owned list keeps the in-scope databases, drops frozen vintages and duplicates, and gives each a priority (e.g. WEO Live first).
  2. Measure dimensions. For each kept database, get_dimensions() tells which dimension holds the indicator (INDICATOR in WEO; INDEX_TYPE, COICOP_1999, TYPE_OF_TRANSFORMATION in CPI-style databases). Each such dimension's values are indexed separately, not every combination.
  3. Write the index. One row per value: database, database name, priority, dimension, code, description, unit if known, in one SQLite file with full-text search (built-in sqlite3, nothing to install). Country and frequency lists stay in the per-database cache.
  4. Refresh monthly and after each WEO round, plus a manual button.

Query time

  1. Phrases. The AI turns the user's words, in any language, into 2–3 English search phrases plus hints (level or rate, real or nominal, local currency or USD, % of GDP).
  2. Retrieve and score, in code. A fixed full-text SQL query, with only the phrases filled in, returns a few hundred rows. Python scores them: word overlap, string similarity, abbreviation expansion, exact-code match, lookup-table boost and database priority. The top ~30 are kept. The AI never writes SQL.
  3. Re-rank. The AI reads those 30 descriptions against the request and picks five. It can only choose from the list.
  4. Select. The five go to the selection screen (step 3). If none fit, the user picks "none of these" and rephrases or names a database.
  5. Learn. Each pick is logged as "words → database + code"; the team promotes frequent pairs into the lookup table.

Several indicators in one request ("GDP growth and inflation") get one candidate list each on the same screen. If the picks land in the same database they share one query (NGDP_RPCH+PCPIPCH) and one file; otherwise they become separate query sheets and files.

6Download and code

Download (step 6)

  • Child process. The first internal-data access opens a browser sign-in that blocks. In a child process the interface stays responsive and shows "waiting for IMF sign-in". An expired session (one hour) becomes "please sign in again". The IMF Python interpreter is started directly, with no shell.
  • Folder. Set by the user in step 4: a text box with the path (Streamlit has no native folder picker; a "Browse…" dialog via tkinter is optional, pywebview has a native one). The last folder is remembered. The AI cannot change it.
  • File name comes from the sheet: <database>_<countries>_<indicator>_<freq>_<start>-<end>.<ext>, shortened when the country list is long. An existing file is never overwritten silently; a suffix is added.
  • Sidecar .json next to the file: the query sheet, the time of download, the package versions. A file found later can be traced and re-run.
  • Values are saved as published, with scale and unit columns added, so nothing is rescaled without saying so.

Code (step 7)

The code is rendered after the download, so it uses the same database, key, period and file path as the file the user already has. Only the language the user picks is shown, with a Copy button and a "Show another language" link. Stata and R code is for copying; it is not run by the agent.

Python

from imf_datatools import idata_utilities
idata_utilities.PRIVATE = True

db  = 'IMF.RES.WEO:WEO_LIVE'
key = 'USA+JPN.NGDP_RPCH.A'   # COUNTRY.INDICATOR.FREQUENCY
df  = idata_utilities.get_idata_data(
        db, key=key, start='2015', end='2026',
        longformat=True)
df.to_csv(r'C:\Users\me\Downloads\WEO_LIVE_....csv',
          index=False)

7Open questions

  1. Index scope. How many databases and indicators are accessible, and which are in scope for v1, in what priority? (A count-only census script run on an IMF machine; the economist sets the priority.)
  2. FTS5. Does the IMF Python's sqlite3 include full-text search? If not, a plain table plus Python scoring is enough at this size.
  3. Frequencies on the candidate list. Showing which frequencies each candidate has needs one extra lookup per candidate, or storing it in the index at build time.
  4. Embeddings. Does the IMF gateway offer an embedding model, as an optional extra score term?
